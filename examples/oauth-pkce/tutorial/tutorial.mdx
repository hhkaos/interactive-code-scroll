## Before you start

In this tutorial you will build a small browser app that signs a user in with ArcGIS OAuth 2.0.
The app uses the ArcGIS Maps SDK for JavaScript, a popup-based OAuth flow, and a callback page that
works from the embedded Preview as well as from a normal browser tab.

You need an ArcGIS Location Platform, ArcGIS Online, or ArcGIS Enterprise account that can create
developer credentials. In ArcGIS Online, that usually means a user type of Creator or higher. If you
want to compare the account setup screens with the product documentation, keep the
[Create OAuth credentials for user authentication](https://developers.arcgis.com/documentation/security-and-authentication/user-authentication/tutorials/create-oauth-credentials-user-auth/)
tutorial open in another tab.

</Step>

<Step id="load-sdk" file="index.html" region="cdn">

## Load the SDK

Start with a plain HTML page and load the ArcGIS Maps SDK for JavaScript from the CDN.

The SDK module bootstraps the ArcGIS web components used in the page, including `arcgis-map`.
It also loads the Calcite components used by the header and sign-in button, so this tutorial does
not need a bundler or a package install step.

</Step>

<Step id="ui" file="index.html" region="ui">

## Build the UI

The app shell is intentionally small: a Calcite navigation bar, one sign-in button, and a map.

The map uses the public `osm` basemap, so the page can render before the user signs in. The OAuth
flow is easier to understand when authentication is tied to one explicit action: pressing
**Sign in**.

</Step>

<Step id="register-app" images={["credential-type-user-alp.png", "oauth-step-1.svg", "oauth-step-2.svg"]}>

## Register your app

Create OAuth credentials in your ArcGIS portal, then copy the **Client ID**. In ArcGIS Location
Platform, open `https://location.arcgis.com`, sign in, and go to **My portal** before creating the
developer credentials item.

Use credentials for **user authentication**, not app authentication with a client secret. Browser
apps should keep only the Client ID in client-side code.

Add a redirect URL for every place where this tutorial will run. In this project, OAuth returns to
the preview callback page:

- Local development: `http://localhost:<port>/preview/oauth-callback.html`
- Published site: `https://<your-site>/<base-path>/preview/oauth-callback.html`

The CLI will print the exact URLs to register. Until then, use the URL shown in your browser and
append `/preview/oauth-callback.html`.

</Step>

<Step id="config" file="main.js" region="config">

## Configure the app

Paste the Client ID from your OAuth credentials.

The **Portal URL** defaults to ArcGIS Online. Keep it as `https://www.arcgis.com` for ArcGIS Online
or ArcGIS Location Platform accounts. Change it only if your organization signs in through an
ArcGIS Enterprise portal.

These values update the code and the Preview immediately. Persisted values are stored only in this
browser.

## Register OAuth information

Import `OAuthInfo` and `IdentityManager`, then register one `OAuthInfo` object.

`appId` is the Client ID from your OAuth credentials. `portalUrl` tells the SDK which portal should
authenticate the user. `popup: true` is important for this tutorial: it opens the ArcGIS sign-in
screen in a popup, so authentication can start from the embedded Preview iframe instead of trying to
load the sign-in page inside the iframe.

The callback file is named explicitly with `popupCallbackUrl`. That makes the relationship between
the registered redirect URL and this project visible in the code. `authNamespace` keeps this demo's
stored sign-in state separate from other apps on the same domain.

</Step>

<Step id="callback" file="oauth-callback.html" region="handler">

## Add the callback page

After sign-in succeeds, ArcGIS redirects the popup to `oauth-callback.html`.

The callback page passes the OAuth response back to the original app window and closes the popup.
This file is part of your tutorial code, so it is shown here, included in downloads, and published
next to the Preview page as `preview/oauth-callback.html`.

If OAuth fails with a redirect URL error, the registered URL and the URL in the browser do not match
exactly. Check the protocol, hostname, port, base path, and filename.

</Step>

<Step id="sign-in" file="main.js" region="sign-in">

## Sign in

Wire the button to `IdentityManager.getCredential()`.

The URL ends in `/sharing` because the ArcGIS sharing endpoint is the secured resource that starts
the portal sign-in flow. When sign-in succeeds, the SDK stores the credential in memory and the app
replaces the button text with the signed-in user name.

Try it in the Preview. If the browser blocks the popup, open the Preview in a new tab and press
**Sign in** there.

</Step>

## Style the page

Finish with just enough CSS to make the map fill the page.

downloaded files work in both the embedded Preview and a standalone tab.
