<Intro>

## Build your first interactive tutorial

InteractiveCodeScroll turns MDX and runnable source files into a static tutorial site. This guide uses the framework itself to show the authoring loop: install the package, create the tutorial folder, write MDX steps and preview the generated result.

> The code panel shows the files you would create in a new tutorial project. The embedded Preview stays collapsed until the tutorial has enough files to make the result useful.

</Intro>

<Step id="install" file="01-project-setup.sh" region="install" preview="collapsed">

## Install the package

Create a project and install Astro with InteractiveCodeScroll. The package is still published under the alpha tag while the authoring API settles.

</Step>

<Step id="scripts" file="01-project-setup.sh" region="scripts" preview="collapsed">

## Add project scripts

The CLI can run directly, but scripts make the tutorial easier to work on and easier to document for other authors.

</Step>

<Step id="folders" file="01-project-setup.sh" region="folders" preview="collapsed">

## Create the tutorial folders

A tutorial folder contains `tutorial.mdx`, runnable files in `code/` and optional visual assets in `images/`. The generated tutorial site is static.

</Step>

<Step id="frontmatter" file="tutorial.mdx" region="frontmatter" preview="collapsed">

## Configure the page

The MDX frontmatter sets the title, Preview mode, default theme and line wrapping. This example uses `preview: both`: an embedded Preview for live feedback and an open-in-tab option for full-screen checks.

</Step>

<Step id="intro" file="tutorial.mdx" region="intro" preview="collapsed">

## Add an introduction

Use `<Intro>` for context before the numbered steps begin. It is not counted as a step and it leaves the tutorial in a no-step state while readers are at the top.

</Step>

<Step id="first-step" file="tutorial.mdx" region="first-step" preview="collapsed">

## Write the first step

Use `<Step>` blocks to connect prose to a file, a region or a set of images. This keeps authoring stable because steps reference ids instead of line numbers.

</Step>

<Step id="regions" file="markers.md" region="regions" preview="expanded">

## Mark code regions

Use comments native to the file type. Region markers are stripped from rendered and downloaded code, so this authoring note shows the marker syntax explicitly while the runnable files stay clean.

</Step>

<Step id="variables" file="markers.md" region="variables" preview="expanded">

## Add editable variables

Add `@var` next to a string literal, then create a matching field in MDX. Try changing the value below: the code panel and embedded Preview update in place.

<VarField name="demoTitle" label="Demo title" placeholder="My first tutorial" persist />

</Step>

<Step id="field" file="tutorial.mdx" region="field" preview="expanded">

## Link the field

The field lives in the MDX step, but its default value comes from the code literal. Clearing the field restores that literal in code, Preview and downloads.

</Step>

<Step id="helpers" file="tutorial.mdx" region="helpers" preview="collapsed">

## Add helper components

Use <Hint id="getting-started-hint" label="hints">Short inline popovers for extra context.</Hint>, Markdown blockquotes for notes and `<details>` for longer optional explanations.

</Step>

<Step id="run" file="02-run-locally.sh" region="run" preview="collapsed">

## Run the tutorial locally

Use dev mode while writing, then build the static site before publishing. Validation fails fast when a step references a missing file, region, image or variable.

</Step>

<Step id="publish" file="03-publish.sh" region="publish" preview="collapsed">

## Build and publish

Run `interactive-code-scroll build` to generate a static site. This repository includes a GitHub Pages workflow that publishes this getting-started tutorial on every push to the default branch.

</Step>
